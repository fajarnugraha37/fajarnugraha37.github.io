# Part 071 — Vocabulary

## 1. Big Picture Terms

| Istilah               | Arti sederhana                            | Dipakai untuk memahami                                          | Catatan senior engineer                                                                     |
| --------------------- | ----------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| **CPQ**               | Configure, Price, Quote                   | Proses memilih produk, menghitung harga, lalu membuat penawaran | CPQ bukan hanya UI quote; biasanya berisi rules, pricing, approval, catalog, dan validation |
| **Quote**             | Penawaran komersial ke customer           | Harga, produk, diskon, term, approval                           | Quote adalah dokumen bisnis yang harus auditable                                            |
| **Order**             | Instruksi eksekusi setelah quote diterima | Fulfillment, provisioning, billing setup                        | Order lebih operasional dibanding quote                                                     |
| **Quote-to-Order**    | Perubahan quote menjadi order             | Handoff dari sales/commercial ke delivery/fulfillment           | Banyak bug muncul di mapping quote line → order line                                        |
| **Quote-to-Cash**     | Siklus dari quote sampai revenue masuk    | CPQ, order, fulfillment, billing, payment                       | CPQ biasanya hanya sebagian dari Q2C                                                        |
| **Order-to-Cash**     | Siklus dari order sampai billing/payment  | Order management, billing, invoicing                            | Fokusnya setelah customer setuju                                                            |
| **Lead-to-Order**     | Siklus dari prospek sampai order          | CRM, opportunity, quote, order                                  | Biasanya integrasi dengan CRM                                                               |
| **Product Catalog**   | Katalog produk yang bisa dijual           | Product, bundle, rule, price                                    | Ini salah satu source of truth terpenting                                                   |
| **Commercial Layer**  | Layer bisnis/penawaran                    | Pricing, discount, margin, quote                                | Beda dengan technical fulfillment layer                                                     |
| **Fulfillment Layer** | Layer eksekusi delivery                   | Provisioning, activation, inventory                             | Order biasanya dikirim ke layer ini                                                         |

## 2. Product & Catalog Terms

| Istilah                    | Arti sederhana                                  | Contoh                                     | Catatan senior engineer                                       |
| -------------------------- | ----------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------- |
| **Product**                | Barang/jasa yang dijual                         | Broadband, mobile plan, cloud package      | Istilah generik; definisi detail biasanya dipecah lagi        |
| **Product Specification**  | Definisi teknis/struktural produk               | Internet Access with bandwidth attribute   | Biasanya reusable dan bukan langsung “produk jualan”          |
| **Product Offering**       | Produk yang ditawarkan secara komersial         | Business Fiber 1Gbps Singapore             | Ini yang biasanya terlihat oleh sales/customer                |
| **Product Offering Price** | Harga yang melekat ke offering                  | $100/month, $500 setup fee                 | Bisa punya effective date dan rule                            |
| **Product Characteristic** | Attribute/parameter produk                      | bandwidth, contract term, region           | Sering dipakai dalam rules dan configuration                  |
| **Configurable Product**   | Produk yang bisa dikonfigurasi                  | VPN dengan bandwidth, site count, SLA      | Membutuhkan configurator/rule engine                          |
| **Bundle**                 | Paket gabungan beberapa produk                  | Internet + Router + Managed Service        | Bundle sering punya dependency dan discount khusus            |
| **Add-on**                 | Produk tambahan opsional                        | Static IP, premium support                 | Biasanya hanya valid jika parent product ada                  |
| **Mandatory Component**    | Komponen wajib dalam bundle                     | Router wajib untuk managed broadband       | Harus divalidasi saat quote/order                             |
| **Optional Component**     | Komponen pilihan                                | Extra support package                      | Bisa mempengaruhi price dan eligibility                       |
| **Product Relationship**   | Relasi antar produk                             | requires, excludes, depends on             | Sangat penting untuk validation                               |
| **Compatibility Rule**     | Aturan produk bisa/tidak bisa digabung          | 5G plan tidak compatible dengan legacy SIM | Mencegah quote invalid                                        |
| **Eligibility Rule**       | Aturan customer boleh membeli produk            | Produk hanya untuk enterprise customer     | Biasanya berdasarkan customer segment, region, contract       |
| **Availability Rule**      | Aturan produk tersedia di lokasi/waktu tertentu | Fiber hanya tersedia di area tertentu      | Sering butuh integrasi coverage/feasibility                   |
| **Catalog Version**        | Versi katalog                                   | Catalog v2026.07                           | Quote/order harus tahu dibuat berdasarkan versi katalog mana  |
| **Effective Dating**       | Tanggal mulai/akhir validity                    | Harga berlaku 1 Jul–31 Dec                 | Critical untuk pricing dan audit                              |
| **Catalog Publish**        | Proses mempromosikan catalog ke active state    | Draft catalog → published catalog          | Jangan anggap catalog update langsung aman                    |
| **Retired Product**        | Produk sudah tidak dijual                       | Legacy broadband plan                      | Existing customer mungkin masih punya produk ini              |
| **Grandfathered Product**  | Produk lama masih dipakai customer existing     | Old corporate mobile plan                  | Tidak bisa dijual baru, tapi masih perlu support modify/renew |

## 3. Configuration & Rule Terms

| Istilah                    | Arti sederhana                          | Contoh                                  | Catatan senior engineer                                       |
| -------------------------- | --------------------------------------- | --------------------------------------- | ------------------------------------------------------------- |
| **Configuration**          | Hasil pemilihan opsi produk             | bandwidth=1Gbps, term=24 months         | Harus valid terhadap catalog rules                            |
| **Configurator**           | Engine/UI untuk menyusun konfigurasi    | Product configuration wizard            | Bisa rule-based, constraint-based, atau custom logic          |
| **Rule Engine**            | Komponen yang menjalankan aturan bisnis | Validate compatibility, price rule      | Hindari menyebar rule di banyak service tanpa ownership jelas |
| **Constraint**             | Batasan yang harus dipenuhi             | bandwidth max 10Gbps                    | Biasanya hard rule                                            |
| **Validation Rule**        | Aturan untuk mengecek correctness       | Contract term wajib dipilih             | Bisa hard validation atau warning                             |
| **Soft Validation**        | Warning, tapi masih bisa lanjut         | Margin rendah tapi belum blocking       | Biasanya butuh approval                                       |
| **Hard Validation**        | Error yang blocking                     | Required field kosong                   | Tidak boleh submit quote/order                                |
| **Dependency Rule**        | A membutuhkan B                         | Managed router requires internet access | Penting untuk bundle                                          |
| **Exclusion Rule**         | A tidak boleh bersama B                 | Promo A tidak boleh dengan discount B   | Sering muncul di pricing/promotion                            |
| **Cardinality**            | Jumlah minimum/maksimum item            | 1 router per site                       | Banyak bug muncul dari cardinality yang tidak dijaga          |
| **Defaulting Rule**        | Rule untuk mengisi nilai default        | Default contract term = 24 months       | Jangan sembunyikan default yang berdampak ke harga            |
| **Derived Attribute**      | Attribute yang dihitung                 | total bandwidth = sum site bandwidth    | Harus jelas kapan dihitung dan oleh siapa                     |
| **Override**               | Perubahan manual terhadap hasil sistem  | Manual discount override                | Harus auditable dan sering butuh approval                     |
| **Configuration Snapshot** | Salinan konfigurasi saat quote dibuat   | Snapshot catalog/product/price          | Penting agar quote lama tidak berubah saat catalog berubah    |

## 4. Pricing Terms

| Istilah                            | Arti sederhana              | Contoh                        | Catatan senior engineer                         |
| ---------------------------------- | --------------------------- | ----------------------------- | ----------------------------------------------- |
| **Price**                          | Harga produk/layanan        | $100/month                    | Bisa terdiri dari banyak charge                 |
| **Price List**                     | Daftar harga                | Enterprise price list         | Bisa berbeda per region/customer/segment        |
| **Rate Card**                      | Tabel tarif                 | Usage rate per GB/minute      | Umum di telco                                   |
| **One-Time Charge / OTC**          | Biaya sekali bayar          | Installation fee              | Kadang disebut setup fee                        |
| **Non-Recurring Charge / NRC**     | Biaya tidak berulang        | Activation fee                | Mirip OTC                                       |
| **Recurring Charge / RC**          | Biaya berulang              | Monthly subscription          | Biasanya MRC/ARC                                |
| **Monthly Recurring Charge / MRC** | Biaya bulanan               | $500/month                    | Metrik komersial penting                        |
| **Annual Recurring Revenue / ARR** | Revenue tahunan berulang    | MRC × 12                      | Dipakai untuk SaaS/subscription                 |
| **Usage Charge**                   | Biaya berdasarkan pemakaian | $0.01 per SMS                 | Perlu rating/charging logic                     |
| **Tiered Pricing**                 | Harga bertingkat            | 1–100 unit $10, 101+ $8       | Perlu hati-hati di boundary                     |
| **Volume Pricing**                 | Harga berdasarkan jumlah    | Diskon jika beli >1000 lines  | Sering dipakai enterprise                       |
| **Discount**                       | Potongan harga              | 10% off                       | Harus jelas berlaku ke item/quote/term tertentu |
| **Promotion**                      | Penawaran sementara         | Free setup until Dec          | Biasanya effective-dated dan rule-heavy         |
| **Price Override**                 | Harga diubah manual         | Sales set price to $90        | High-risk; perlu approval dan audit             |
| **Discount Override**              | Diskon diubah manual        | Sales gives 35% discount      | Sering terkait margin threshold                 |
| **Margin**                         | Selisih revenue dan cost    | Price - cost                  | Penting untuk approval                          |
| **Margin Threshold**               | Batas minimum margin        | Minimum margin 20%            | Jika dilanggar, perlu approval                  |
| **Cost Model**                     | Model biaya internal        | Network cost, equipment cost  | Tidak selalu visible ke customer                |
| **Tax**                            | Pajak                       | VAT/GST                       | Bisa tergantung region dan product type         |
| **Currency**                       | Mata uang transaksi         | USD, AUD, SGD                 | Multi-currency butuh FX/effective date          |
| **Proration**                      | Perhitungan proporsional    | Mulai layanan di tengah bulan | Penting untuk subscription                      |
| **Price Recalculation**            | Hitung ulang harga          | Setelah item berubah          | Harus jelas trigger-nya                         |
| **Price Lock**                     | Harga dikunci               | Quote valid 30 hari           | Mencegah harga berubah tiba-tiba                |
| **Quote Validity**                 | Masa berlaku quote          | Valid until 31 Aug            | Setelah expired, biasanya perlu reprice         |

## 12. Event-Driven Terms

| Istilah                    | Arti sederhana                                  | Contoh                               | Catatan senior engineer                              |
| -------------------------- | ----------------------------------------------- | ------------------------------------ | ---------------------------------------------------- |
| **Domain Event**           | Fakta bisnis yang sudah terjadi                 | QuoteAccepted, OrderSubmitted        | Event harus bernama past tense                       |
| **Command**                | Instruksi melakukan sesuatu                     | SubmitQuote, CancelOrder             | Command bisa gagal; event adalah fakta               |
| **Aggregate**              | Boundary konsistensi domain                     | Quote aggregate, Order aggregate     | Menentukan transaction boundary                      |
| **Event Producer**         | Service yang publish event                      | Quote service emits QuoteAccepted    | Producer owns event meaning                          |
| **Event Consumer**         | Service yang consume event                      | Order service consumes QuoteAccepted | Consumer harus tahan duplicate/out-of-order          |
| **Topic**                  | Kanal event Kafka                               | quote-events                         | Topic design mempengaruhi scale dan ordering         |
| **Partition Key**          | Key untuk menentukan partition                  | quoteId/orderId                      | Menentukan ordering guarantee                        |
| **Consumer Group**         | Grup consumer yang berbagi workload             | order-service group                  | Satu event diproses satu consumer per group          |
| **Offset**                 | Posisi baca consumer                            | Kafka offset                         | Salah commit offset bisa kehilangan/ulang event      |
| **At-Least-Once Delivery** | Event bisa terkirim lebih dari sekali           | Duplicate event possible             | Maka idempotency wajib                               |
| **Exactly-Once Semantics** | Jaminan khusus Kafka untuk skenario tertentu    | Transactional producer               | Jangan dianggap menyelesaikan semua duplicate bisnis |
| **Outbox Pattern**         | Simpan DB change dan event dalam satu transaksi | quote + outbox row                   | Menghindari DB updated tapi event tidak terkirim     |
| **Inbox Pattern**          | Catat event yang sudah diproses                 | processed_event table                | Mencegah duplicate processing                        |
| **Poison Message**         | Event yang selalu gagal diproses                | Bad payload                          | Harus masuk DLQ/manual handling                      |
| **Consumer Lag**           | Jarak consumer tertinggal dari latest event     | Lag 100k messages                    | Indikasi bottleneck atau failure                     |
| **Event Ordering**         | Urutan event terjaga                            | QuoteCreated before QuoteAccepted    | Biasanya hanya terjamin dalam partition yang sama    |

## 13. State & Lifecycle Terms

| Istilah              | Arti sederhana                     | Contoh                                  | Catatan senior engineer                               |
| -------------------- | ---------------------------------- | --------------------------------------- | ----------------------------------------------------- |
| **State**            | Kondisi saat ini                   | Quote = Draft                           | Harus eksplisit                                       |
| **Status**           | Label state bisnis                 | Approved, Submitted                     | Jangan campur status teknis dan bisnis tanpa definisi |
| **State Transition** | Perubahan state                    | Draft → Submitted                       | Harus divalidasi                                      |
| **Transition Guard** | Syarat sebelum pindah state        | Must pass validation                    | Cocok untuk modelling formal                          |
| **Terminal State**   | State akhir                        | Cancelled, Completed                    | Biasanya tidak boleh berubah lagi                     |
| **Mutable State**    | State masih bisa diedit            | Draft quote                             | Batasi field yang bisa berubah                        |
| **Immutable State**  | State tidak boleh diubah           | Accepted quote                          | Gunakan revision/amendment                            |
| **Lifecycle**        | Alur hidup entity                  | Quote lifecycle                         | Harus terdokumentasi                                  |
| **Sub-State**        | State detail di bawah status utama | Order In Progress + Waiting Appointment | Hindari status explosion                              |
| **Business State**   | State menurut bisnis               | Approved                                | Beda dari technical processing state                  |
| **Processing State** | State teknis pemrosesan            | Event published, retrying               | Jangan tampilkan mentah ke user tanpa konteks         |
| **SLA Clock**        | Pengukuran waktu terhadap SLA      | Approval due in 2 days                  | Perlu pause/resume rules                              |
| **Reopen**           | Membuka kembali entity             | Reopen rejected quote                   | Harus jelas allowed transition-nya                    |

## 15. Istilah yang sering terlihat mirip tapi beda

| **Fulfillment**           | **Provisioning**        | Fulfillment lebih luas; provisioning adalah aktivasi teknis                          |
