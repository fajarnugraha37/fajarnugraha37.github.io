# Linux Cheat Sheet — Senior Software Engineer Onboarding

## 0. Mental Model Linux

Linux bisa dipahami sebagai beberapa layer:

```text
Application
  ↓
Shell / CLI tools
  ↓
Userland utilities: coreutils, grep, awk, sed, ssh, systemctl
  ↓
System services: systemd, journald, cron, sshd, docker
  ↓
Kernel: process, memory, filesystem, networking, cgroup, namespace
  ↓
Hardware / VM / Container / Cloud instance
```

Hal penting untuk engineer:

| Area | Yang perlu dipahami |
|---|---|
| Process | PID, parent-child, signal, exit code |
| Filesystem | permission, ownership, mount, disk usage |
| Networking | port, socket, DNS, routing, firewall |
| Service lifecycle | start, stop, restart, enable, logs |
| Observability | logs, CPU, memory, I/O, network |
| Security | user, group, sudo, SSH, permission |
| Runtime | environment variable, systemd unit, container |

# 3. Permission, Ownership, User

## Format permission

Contoh:

```bash
-rwxr-x---
```

Artinya:

```text
-     rwx     r-x     ---
type  owner   group   others
```

| Symbol | Meaning |
|---|---|
| `r` | read |
| `w` | write |
| `x` | execute |
| `-` | no permission |

## Permission numerik

| Mode | Meaning |
|---|---|
| `7` | read + write + execute |
| `6` | read + write |
| `5` | read + execute |
| `4` | read only |
| `0` | no access |

```bash
chmod 755 script.sh         # owner rwx, group rx, others rx
chmod 644 file.txt          # owner rw, group r, others r
chmod +x script.sh          # tambah executable
```

## Ownership

```bash
chown user file.txt
chown user:group file.txt
chown -R user:group app/
```

## User dan group

```bash
whoami                      # user sekarang
id                          # user id, group id
groups                      # group user
sudo command                # run sebagai root
su - username               # switch user
```

## User management

```bash
sudo useradd -m appuser
sudo passwd appuser
sudo usermod -aG sudo appuser       # Ubuntu/Debian
sudo usermod -aG wheel appuser      # RHEL/CentOS/Fedora
```

# 7. Systemd dan Service Lifecycle

Mayoritas distro modern memakai `systemd`.

## Basic service command

```bash
sudo systemctl status nginx
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx

```

## List services

```bash
systemctl list-units --type=service
systemctl list-units --failed
```

## Inspect service

```bash
systemctl cat nginx
systemctl show nginx
```

## Journal logs

```bash
journalctl -u nginx
journalctl -u nginx -f
journalctl -u nginx --since "1 hour ago"
journalctl -u nginx --since today
journalctl -xe
```

## Contoh systemd unit sederhana

```ini
[Unit]
Description=My Java App
After=network.target

[Service]
User=appuser
WorkingDirectory=/opt/myapp
ExecStart=/usr/bin/java -jar app.jar
Restart=always
RestartSec=5
Environment=APP_ENV=prod
Environment=JAVA_OPTS=-Xms512m -Xmx1024m

[Install]
WantedBy=multi-user.target
```

Apply:

```bash
sudo systemctl daemon-reload
sudo systemctl enable myapp
sudo systemctl start myapp
sudo systemctl status myapp
```

# 24. Linux Failure Mode Table

| Failure | Typical Root Cause | First Commands |
|---|---|---|
| App crash on startup | missing env/config, bad permission, dependency down | `systemctl status`, `journalctl -u` |
| Port unreachable | service down, firewall, bind localhost only | `ss -lntp`, `curl -v`, `ip route` |
| Slow app | CPU, memory, DB, network, GC, disk I/O | `top`, `free`, `iostat`, logs |
| Disk full | logs, docker images, temp files | `df -h`, `du -ah` |
| No space but disk not full | inode exhausted | `df -i` |
| Cannot SSH | key permission, firewall, sshd down, wrong user | `ssh -v`, `journalctl -u sshd` |
| DNS failure | resolver/config/network | `dig`, `cat /etc/resolv.conf` |
| DB connection fail | credential, DNS, firewall, DB down | `pg_isready`, `nc -zv host 5432` |
| Service restarts repeatedly | systemd restart loop, app crash | `systemctl status`, `journalctl -u` |
| Container cannot access host/service | Docker network, bridge, DNS, firewall | `docker inspect`, `ss`, `ip route` |

# 19. Redirection

Redirection diproses sebelum command dieksekusi, dan urutannya signifikan. Misalnya `cmd >file 2>&1` mengarahkan stdout dan stderr ke file, sedangkan `cmd 2>&1 >file` membuat stderr mengikuti stdout lama, lalu stdout diarahkan ke file. ([Case ITS](https://tiswww.case.edu/php/chet/bash/bashref.html))

| Syntax | Arti |
|---|---|
| `>` | redirect stdout, overwrite |
| `>>` | redirect stdout, append |
| `<` | redirect stdin |
| `2>` | redirect stderr |
| `2>>` | append stderr |
| `2>&1` | stderr ke stdout |
| `&>` | stdout + stderr ke file, Bash |
| `&>>` | append stdout + stderr, Bash |
| `/dev/null` | buang output |

```bash
command > out.log
command 2> err.log
command > all.log 2>&1
command &> all.log
command >> app.log 2>&1
command >/dev/null 2>&1
```

## Safe overwrite protection

# 46. Common Pitfalls

## 1. Unquoted variable

```bash
rm $file      # salah
rm -- "$file" # benar
```

## 2. Parsing `ls`

```bash
for file in $(ls); do   # salah
  echo "$file"
done
```

Benar:

```bash
for file in *; do
  [[ -e "$file" ]] || continue
  echo "$file"
done
```

## 3. Losing exit status

```bash
output="$(cmd)"
status=$?
```

Ini masih oke.

Tapi ini berbahaya:

```bash
local output="$(cmd)"
```

Karena `local` bisa menutupi exit status command substitution. Lebih aman:

```bash
local output
output="$(cmd)"
```

## 4. `grep` no match dianggap failure

```bash
set -e

grep "ERROR" app.log
echo "done"
```

Kalau tidak ada match, `grep` exit `1`, script bisa berhenti. Pattern:

```bash
if grep -q "ERROR" app.log; then
  echo "error found"
else
  echo "no error"
fi
```

## 5. `while read` dari pipe kehilangan state

```bash
count=0
printf '%s\n' a b | while read -r x; do
  ((count++))
done
echo "$count"   # bisa 0
```

Gunakan process substitution:

```bash
count=0
while read -r x; do
  ((count++))
done < <(printf '%s\n' a b)
echo "$count"
```

## 6. `set -e` dianggap magic safety

Salah. `set -e` punya banyak pengecualian. Gunakan juga explicit checks, `trap`, `pipefail`, dan test command dengan `if`. ([GNU](https://www.gnu.org/software/bash/manual/html_node/The-Set-Builtin.html))

## 7. Redirection order salah

```bash
cmd 2>&1 >out.log    # stderr tidak ikut ke out.log
cmd >out.log 2>&1    # stdout dan stderr ke out.log
```

Order redirection diproses kiri ke kanan. ([Case ITS](https://tiswww.case.edu/php/chet/bash/bashref.html))

## Retry with backoff

```bash
retry_backoff() {
  local max_attempts="$1"
  shift

  local attempt=1
  local delay=1

  until "$@"; do
    if (( attempt >= max_attempts )); then
      echo "Command failed after $attempt attempts: $*" >&2
      return 1
    fi

    echo "Attempt $attempt failed; retrying in ${delay}s..." >&2
```

# 54. Golden Rules

| Rule | Alasan |
|---|---|
| Quote variable: `"$var"` | Mencegah word splitting dan globbing tidak sengaja |
| Pakai `"$@"`, bukan `$@` | Menjaga argumen dengan spasi |
| Pakai `printf`, bukan `echo` untuk data tidak pasti | `echo` punya variasi behavior untuk escape/option |
| Pakai `bash -n` dan `shellcheck` | Menangkap bug sebelum runtime |
| Jangan percaya `set -e` sepenuhnya | Banyak pengecualian |
| Pakai `pipefail` untuk pipeline penting | Failure di tengah pipeline tidak tertutup |
| Jangan parse `ls` | Nama file bisa mengandung spasi/newline |
| Pakai `mktemp` | Aman untuk temp file |
| Pakai `trap` untuk cleanup | Mengurangi leak file/process |
| Jangan log secret | CI/systemd logs sering tersimpan lama |
| Bedakan Bash dan POSIX `sh` | Menghindari script jalan di shell yang salah |
| Destructive command harus ada guard | Mengurangi risiko incident |

# 55. Minimal Bash Script Skeleton Production-Grade

```bash
#!/usr/bin/env bash
set -Eeuo pipefail
IFS=$'\n\t'

SCRIPT_NAME="$(basename "$0")"

usage() {
  cat <<EOF
Usage:
  $SCRIPT_NAME --env ENV --artifact FILE [--dry-run]

Options:
  --env ENV        dev|staging|prod
  --artifact FILE  artifact path
  --dry-run        print commands only
  -h, --help       show help
EOF
}

log() {
  local level="$1"
  shift
  printf '%s [%s] %s\n' "$(date -Is)" "$level" "$*" >&2
}

die() {
  log ERROR "$*"
  exit 1
}

require_cmd() {
  command -v "$1" >/dev/null 2>&1 || die "Missing command: $1"
}

run() {
  printf '+'
  printf ' %q' "$@"
  printf '\n' >&2

  if [[ "$DRY_RUN" == false ]]; then
    "$@"
  fi
}

cleanup() {
  :
}

trap cleanup EXIT
trap 'die "Failed at line $LINENO: $BASH_COMMAND"' ERR

ENVIRONMENT=""
ARTIFACT=""
DRY_RUN=false

while (($# > 0)); do
  case "$1" in
    --env)
      ENVIRONMENT="${2:?--env requires value}"
      shift 2
      ;;
    --artifact)
      ARTIFACT="${2:?--artifact requires value}"
      shift 2
      ;;
    --dry-run)
      DRY_RUN=true
      shift
      ;;
    -h|--help)
      usage
      exit 0
      ;;
    *)
      usage >&2
      die "Unknown argument: $1"
      ;;
  esac
done

main() {
  require_cmd java
  require_cmd curl

  [[ -n "$ENVIRONMENT" ]] || die "--env is required"
  [[ -f "$ARTIFACT" ]] || die "artifact not found: $ARTIFACT"

  case "$ENVIRONMENT" in
    dev|staging|prod) ;;
    *) die "invalid env: $ENVIRONMENT" ;;
  esac

  log INFO "Deploying artifact=$ARTIFACT env=$ENVIRONMENT dry_run=$DRY_RUN"

  run ls -lah "$ARTIFACT"
}

main "$@"
```

# 56. Failure Mode Table

| Symptom | Kemungkinan Penyebab | Cek |
|---|---|---|
| Script jalan di local tapi gagal di CI | Shell berbeda, env beda, working directory beda | `echo "$SHELL"`, `pwd`, `env`, shebang |
| `command not found` | PATH beda, dependency belum install | `command -v cmd`, `echo "$PATH"` |
| Variable kosong | Env belum diset, typo variable, `set -u` | `printenv`, `${VAR:?required}` |
| Pipeline sukses padahal command awal gagal | Tidak pakai `pipefail` | `set -o pipefail` |
| Script stop saat `grep` tidak ketemu | `grep` exit `1`, terkena `set -e` | bungkus dalam `if grep -q` |
| File dengan spasi gagal | Variable tidak di-quote | `"$file"` |
| Loop line-by-line rusak | Pakai `for line in $(cat file)` | `while IFS= read -r` |
| Cleanup tidak jalan | Tidak ada `trap EXIT` | tambah cleanup trap |
| Secret bocor | `set -x`, echo token, command log | matikan trace saat secret |
| Stderr tidak masuk log | Redirection order salah | `cmd >log 2>&1` |
| State variable hilang setelah loop | Loop berjalan di subshell pipeline | process substitution |
| Script tidak portable | Bash feature dipakai di `/bin/sh` | ubah shebang ke Bash atau tulis POSIX |

# 3. `java`

`java` menjalankan aplikasi Java dengan membuat JVM, memuat class utama, dan memanggil `public static void main(String[] args)`. Ia bisa menjalankan main class, executable JAR, module, dan source-file program. ([Oracle Docs](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html))

## Common usage

```bash
java com.example.Main

java -jar app.jar
java -m com.example.app/com.example.Main

```

## Common runtime options

```bash
java -Xms512m -Xmx2g -jar app.jar
java -Dspring.profiles.active=prod -jar app.jar
java -Duser.timezone=UTC -jar app.jar
java -XX:+UseG1GC -jar app.jar
java -Xlog:gc*:file=gc.log:time,level,tags -jar app.jar
```

## Classpath vs module path

```bash
java -cp "lib/*:target/classes" com.example.Main
java --module-path mods -m com.example.app/com.example.Main
```

```powershell
java -cp "lib/*;target/classes" com.example.Main
```

## Source-file mode

```bash
java HelloWorld.java
java --source 17 ScriptWithoutJavaExtension
```

Useful untuk quick script atau reproduksi kecil tanpa Maven.

## Arg file

```bash
java @java-options.txt
```

```text
-Xms512m
-Xmx2g
-Dapp.env=dev
-jar
app.jar
```

## Production notes

| Concern | Catatan |
|---|---|
| `-jar` ignores classpath | Saat memakai `-jar`, classpath lain via `-cp` tidak dipakai sebagai user class source; dependency biasanya harus di manifest atau fat jar. |
| `JDK_JAVA_OPTIONS` | Bisa prepend opsi ke launcher; hati-hati di CI/container karena dapat mengubah runtime tanpa terlihat di command utama. |
| GC log | Gunakan `-Xlog:gc*` di Java modern. |
| Heap in container | Pastikan limit container dan `-Xmx` selaras. |
| Timezone | Explicit `-Duser.timezone=UTC` sering mengurangi bug temporal. |

# 5. `javac`

`javac` membaca source Java dan mengompilasi deklarasi menjadi class file untuk JVM; ia juga bisa menjalankan annotation processing. Oracle merekomendasikan output terpisah dengan `-d`, bukan menulis `.class` di direktori source. ([Oracle Docs](https://docs.oracle.com/en/java/javase/25/docs/specs/man/javac.html))

## Basic compile

```bash
javac Hello.java

```

## Compile dengan classpath

```bash

```

## Compile banyak source

```bash
find src/main/java -name "*.java" > sources.txt
javac -d out @sources.txt
```

## Target release

```bash
javac --release 17 -d out @sources.txt
javac --release 21 -d out @sources.txt
```

Prefer `--release`, bukan kombinasi manual `-source` + `-target`, karena `--release` juga membatasi API platform sesuai versi target.

## Lint

```bash
javac -Xlint:all -d out @sources.txt
javac -Xlint:deprecation -d out @sources.txt
javac -Werror -Xlint:all -d out @sources.txt
```

## Module compile

```bash
javac --module-source-path src \
      -d mods \
      --module com.example.app
```

## Annotation processing

```bash
javac -processor com.example.MyProcessor -d out @sources.txt
javac -proc:only -processor com.example.MyProcessor @sources.txt
javac -proc:none -d out @sources.txt
```

## Failure clues

| Symptom | Cek |
|---|---|
| `cannot find symbol` | Missing import, wrong classpath, compile order, generated source belum dibuat |
| `package ... does not exist` | Dependency tidak ada di classpath/module-path |
| `class file has wrong version` | Dependency dikompilasi dengan Java lebih baru |
| Annotation processor tidak jalan | Cek processor path, Maven compiler plugin, `-proc:none` |
| Works in IDE, fails in CLI | IDE classpath berbeda dari Maven/CLI |

# 7. `jarsigner`

`jarsigner` punya dua fungsi: menandatangani JAR dan memverifikasi signature/integrity JAR. Ia memakai key/certificate dari keystore; `keytool` dipakai untuk membuat dan mengelola keystore tersebut. ([Oracle Docs](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jarsigner.html))

## Sign JAR

```bash
jarsigner \
  -keystore release.p12 \
  -storetype PKCS12 \
  -signedjar app-signed.jar \
  app.jar release-key
```

## Verify JAR

```bash
jarsigner -verify app-signed.jar
jarsigner -verify -verbose -certs app-signed.jar
jarsigner -verify -strict app-signed.jar
```

## Timestamp signing

```bash
jarsigner \
  -keystore release.p12 \
  -storetype PKCS12 \
  -tsa http://timestamp.example.com \
  -signedjar app-signed.jar \
  app.jar release-key
```

## Notes

| Topic | Catatan |
|---|---|
| Default keystore | Default keystore type modern adalah `PKCS12`, sedangkan `JKS` adalah legacy/proprietary Java format. ([Oracle Docs](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jarsigner.html)) |
| `-strict` | Treat severe warning as error. Cocok untuk CI release gate. |
| Timestamp | Penting agar signature tetap bisa dievaluasi terhadap waktu signing certificate masih valid. |
| Disabled algorithms | JAR dengan algoritma disabled bisa diperlakukan sebagai unsigned. |
| Secret | Hindari password di shell history; gunakan prompt, protected mechanism, atau CI secret. |

# 36. Tool Selection Rules

| Need | Prefer | Avoid / Caveat |
|---|---|---|
| Find PID | `jcmd -l`, `jps -l`, `ps aux` | Jangan parse `jps` untuk kontrak jangka panjang |
| Thread dump | `jcmd Thread.print` | `jstack` legacy/unsupported |
| Heap dump | `jcmd GC.heap_dump` | `jmap` boleh, tapi unsupported |
| JFR recording | `jcmd JFR.*` + `jfr` | Jangan recording tanpa durasi/path |
| GC stats quick | `jstat -gcutil` | Output unstable untuk script permanen |
| Runtime flags | `jcmd VM.flags` | `jinfo` unsupported |
| Core dump | `jhsdb` | Jangan attach live process sembarangan |
| Dependency audit | `jdeps` | Dynamic reflection bisa miss |
| Deprecated API scan | `jdeprscan` | Hanya Java SE deprecated API |
| Runtime image | `jlink` | Harus rebuild saat JDK patch |
| Native package | `jpackage` | No cross-platform package build |
| Keystore/cert | `keytool` | Jangan taruh password di shell history |
| Signed JAR | `jarsigner` | Pakai `-strict` di CI |
| Quick static server | `jwebserver` | Tidak untuk production HTTPS/API server |
| Java REPL | `jshell` | Jangan untuk production automation |
| Legacy script shell | `jrunscript` | Deprecated |

# 37. Production Safety Table

| Tool | Risk |
|---|---|
| `jcmd GC.heap_dump` | Disk penuh, pause, sensitive data in heap |
| `jcmd GC.class_histogram` | Bisa high impact pada heap besar |
| `jmap -dump` | Heavy dan unsupported |
| `jstack` | Unsupported; prefer `jcmd Thread.print` |
| `jhsdb` live attach | Bisa membuat target hang/crash |
| `jstatd` | No authentication; avoid production exposure |
| `jconsole` remote JMX | Secure dengan auth/TLS; jangan expose public |
| `jdb` / JDWP | Remote debug port sangat sensitif |
| `jwebserver -b 0.0.0.0` | Bisa leak file static |
| `serialver` | Loads/initializes classes; jangan untuk untrusted class |
| `keytool` / `jarsigner` | Secret handling dan algorithm policy penting |

```text id="zgm8t9"
│  ├─ dependencies
│  ├─ dependencyManagement
│  ├─ build plugins
│  ├─ profiles
│  └─ distributionManagement
│
├─ Lifecycle
│  ├─ clean
│  ├─ default
│  └─ site
│
├─ Plugins
│  ├─ compiler
│  ├─ surefire
│  ├─ failsafe
│  ├─ jar
│  ├─ install
│  ├─ deploy
│  └─ dependency
│
├─ Repositories
│  ├─ local: ~/.m2/repository

│
└─ Reactor

```

Maven bekerja dari **Project Object Model / POM**. POM mendeskripsikan “apa” project-nya, sedangkan lifecycle dan plugin menentukan “kapan” dan “bagaimana” build dijalankan. Maven sendiri pada dasarnya adalah **plugin execution framework**: compile, test, package, install, deploy, dependency analysis, dan report semuanya dikerjakan oleh plugin. ([Apache Maven](https://maven.apache.org/pom.html))

## 2. Command Paling Sering Dipakai

```bash id="vdx5i2"
mvn -v                         # cek Maven + Java runtime
mvn validate                    # validasi POM/project
mvn compile                     # compile main source
mvn test                        # run unit test
mvn package                     # build artifact: jar/war/etc
mvn verify                      # run checks + integration test verification
mvn install                     # install artifact ke local repo
mvn deploy                      # publish artifact ke remote repo
mvn clean                       # hapus target/
mvn clean package               # clean lalu build package
mvn clean verify                # clean lalu full verification
```

Lifecycle utama Maven ada tiga: **clean**, **default**, dan **site**. Lifecycle `default` berisi phase seperti `validate`, `compile`, `test`, `package`, `verify`, `install`, dan `deploy`; menjalankan phase yang lebih akhir otomatis menjalankan phase sebelumnya dalam lifecycle yang sama. ([Apache Maven](https://maven.apache.org/guides/introduction/introduction-to-the-lifecycle.html))

## 7. Lifecycle dan Phase

```text id="f3d27f"

├─ test
├─ package
```

| Phase | Fungsi |
|---|---|

## 8. Goal vs Phase

```bash id="a0q1eh"
mvn package
mvn compiler:compile
mvn dependency:tree
mvn help:effective-pom
```

| Istilah | Contoh | Makna |
|---|---|---|
| Phase | `package` | Tahap lifecycle |
| Plugin | `compiler` | Komponen yang menjalankan pekerjaan |
| Goal | `compiler:compile` | Task spesifik dari plugin |
| Execution | binding plugin goal ke phase | Goal dijalankan otomatis di phase tertentu |

Rule praktis:


## 12. Dependencies

## 13. Dependency Scope

| Scope | Compile classpath | Runtime classpath | Test classpath | Transitive | Use case |
|---|---:|---:|---:|---:|---|
| `compile` | Ya | Ya | Ya | Ya | Default |
| `provided` | Ya | Tidak | Ya | Tidak | Servlet/Jakarta API disediakan container |
| `runtime` | Tidak | Ya | Ya | Ya | JDBC driver |
| `test` | Tidak | Tidak | Ya | Tidak | JUnit, Mockito |
| `system` | Ya | Ya | Ya | Tidak umum | Legacy local JAR |
| `import` | Khusus `dependencyManagement` | N/A | N/A | N/A | Import BOM |

Maven mendefinisikan enam scope: `compile`, `provided`, `runtime`, `test`, `system`, dan `import`. Scope menentukan classpath dan transitivity. ([Apache Maven](https://maven.apache.org/guides/introduction/introduction-to-dependency-mechanism.html))

## 21. Mirror

| Option | Fungsi |

## 42. Enforcer Rules

Gunakan `maven-enforcer-plugin` untuk build guardrail.

```xml id="oqqbve"
<plugin>
  <groupId>org.apache.maven.plugins</groupId>
  <artifactId>maven-enforcer-plugin</artifactId>
  <version>3.6.2</version>
  <executions>
    <execution>
      <id>enforce</id>
      <goals>
        <goal>enforce</goal>
      </goals>
      <configuration>
        <rules>
          <requireMavenVersion>
            <version>[3.9.0,)</version>
          </requireMavenVersion>
          <requireJavaVersion>
            <version>[17,)</version>
          </requireJavaVersion>
          <dependencyConvergence/>
        </rules>
      </configuration>
    </execution>
  </executions>
</plugin>
```

Use case:

| Rule | Fungsi |
|---|---|
| `requireJavaVersion` | Paksa JDK tertentu |
| `requireMavenVersion` | Paksa Maven version |
| `dependencyConvergence` | Cegah dependency conflict |
| `banDuplicatePomDependencyVersions` | Cegah duplicate dependency declaration |
| `bannedDependencies` | Blok dependency tertentu |

## 47. Common Maven Errors

| Error | Arti umum | Cek |
|---|---|---|
| `Could not resolve dependencies` | Dependency tidak bisa diunduh | repo, mirror, proxy, credential, versi |
| `Could not find artifact` | Artifact tidak ada di repo yang dicari | koordinat, repository, snapshot/release repo |
| `Non-resolvable parent POM` | Parent POM tidak ditemukan | parent version, relativePath, repo |
| `Source option 5 is no longer supported` | Compiler default terlalu lama | set `maven.compiler.release` |
| `No compiler is provided in this environment` | Pakai JRE, bukan JDK | cek `JAVA_HOME` |
| `Failed to execute goal surefire:test` | Unit test gagal / surefire config issue | `target/surefire-reports` |
| `Failed to execute goal failsafe:verify` | Integration test gagal | `target/failsafe-reports` |
| `PKIX path building failed` | TLS truststore/corporate cert issue | truststore, proxy, internal CA |
| `Return code is: 401` | Unauthorized deploy/download | `settings.xml` server id/credential |
| `Return code is: 403` | Forbidden | permission repo |
| `Checksum validation failed` | Artifact corrupt/tampered/proxy issue | local cache, repo manager |

## 51. Maven Anti-Patterns

| Anti-pattern | Kenapa buruk |
|---|---|
| Tidak pin plugin version | Build bisa berubah diam-diam |
| Mengandalkan transitive dependency langsung | Bisa rusak saat upstream berubah |
| Credential di `pom.xml` | Secret leak |
| Terlalu banyak profile environment-specific | Build tidak portable |
| `system` scope | Tidak reproducible |
| `mvn integration-test` langsung | Teardown bisa tidak jalan; pakai `mvn verify` |
| `-DskipTests` permanen di CI | Quality gate hilang |
| Parent POM terlalu kompleks | Semua module terkena coupling |
| Dependency exclusion membabi buta | Bisa menyembunyikan runtime issue |
| Tidak pakai internal repository manager | Lambat, tidak deterministic, supply-chain risk |

## 52. Golden Rules

```text id="5wfgci"
1. Untuk CI, default command: ./mvnw -B -ntp clean verify
2. Gunakan Maven Wrapper.
3. Pin semua plugin version.
4. Direct dependency harus dideklarasikan langsung.
5. Versi dependency dikontrol di dependencyManagement/BOM.
6. Credential hanya di settings.xml / CI secret.
7. Untuk integration test, jalankan mvn verify.
8. Untuk multi-module, kuasai -pl, -am, -amd, -rf.
9. Untuk debugging, mulai dari effective-pom, active-profiles, dependency:tree.
10. Untuk enterprise, gunakan internal repository manager dan mirror.
```
